## 1. 这一档存在的理由

它是「第 0 档」：没有注意力、没有残差、没有孪生、没有差分、没有预训练。
所有后续改进（B1 换编码器、M0/M1/M2 换融合）都必须和它比，否则说不清涨点来自哪里。

**刻意不做的三件事**，都是为了保住「干净基线」这个身份：

1. 不加载 ImageNet 权重——一旦加载，「涨点来自结构还是预训练」永远讲不清；
2. 不用转置卷积上采样——用 bilinear + 1×1，避免棋盘格伪影污染边界指标；
3. 不加深、不加宽——参数量压到 7.85 M，让 8 GB 卡上 bs24 只占 3.3 GB。

## 2. 结构（实测逐层）

| 层 | 操作 | 通道 | 分辨率 | 感受野 | 参数量 |
|---|---|---|---|---|---|
| stem | 2×(3×3 conv-BN-ReLU) | 6 → 32 | 256² | 5 px | 0.011 M |
| down1 | maxpool + 双卷积 | 32 → 64 | 128² | 14 px | 0.056 M |
| down2 | 同上 | 64 → 128 | 64² | 32 px | 0.222 M |
| down3 | 同上 | 128 → 256 | 32² | 68 px | 0.886 M |
| down4 | 同上 | 256 → 512 | 16² | 140 px | 3.541 M |
| decoder | 4×bilinear + skip 拼接 + 双卷积 | → 32 | 256² | — | 3.14 M |

**容量分布是这一档的已知短板**：45.1% 参数堆在 16×16 瓶颈，stem 仅占 0.14%，
却要在一层之内完成「A/B 配对 → 差异提取 → 边缘定位」。这正是 B1 存在的机制性理由。

| 指标 | 值 |

## 4. 怎么跑

```bash
# 从项目根目录执行（数据与训练脚本都在文件夹外，所有档位共用）
python train.py --model B0 --epochs 30 --batch-size 24
python val.py --ckpt run/train/B0_exp1/weights/best_model.pth --split test --thr-sweep 0.2:0.8:0.05
python predict.py --ckpt run/train/B0_exp1/weights/best_model.pth --n 8
```

产物落在 `run/train/B0_expN/`（目录名带档位代号）。

## 5. 已知限制（面试要主动说）

1. 边界精度受限于浅层容量（stem 只有 32 通道），这是 B1 要解决的问题；
2. 早融合把「找差异」的负担压在第一层，所以它对 M1 的差距会**偏大**——
   讲「我的方法比基线强多少」时必须同时报 M1−B1 这个更严格的对照；
3. 未实现早停，靠 `best_model.pth` 按 val F1 保最优。

## 6. 与其他档的关系

- 下游 **B1**：只把编码器换成 ResNet34 + ImageNet 预训练（其余不动），用来度量「容量 + 预训练」值多少点。
- 下游 **M0/M1/M2**：在 B1 基础上换融合方式（早融合 → 孪生 + 逐层融合），用来度量「显式差分」值多少点。
