# L1 · 轻量版：M1 窄化 + ONNX / TensorRT

| 项 | 值 |
|---|---|
| 代号 | **L1**（Light 族；序号 1 = 第一个轻量变体） |
| 一句话 | M1 的 `width × 0.5` 窄化版，配 ONNX/TensorRT fp16/int8 三档部署对比 |
| 参数量 | 目标 ≤ M1 的 40% |
| 状态 | ⏳ **阶段 4**：M1 正式结果出来后做 |

## 为什么必做（不是选做）

JD 里「轻量化 / 推理加速 / 国产化部署」出现频率上升最快，而候选人里会的人最少。
1 天成本换一个高频加分项，是全项目性价比最高的一步。

## 通过线（计划 §4.3）

| 指标 | 要求 |
|---|---|
| 参数量 | ≤ M1 的 40% |
| 单张时延 | ≤ M1 的 60% |
| F1 掉点 | ≤ 1.5 点 |
| ONNX fp16 加速 | ≥ 1.3×（相对 PyTorch） |
| TensorRT int8 | 掉点如实报，不美化 |

## 实现注意

1. 窄化要**统一缩放所有通道**（含编码器与融合层），不能只改解码器——否则对比不公平；
2. 导出 ONNX 时固定 256×256 输入并开 `dynamic_axes=False` 以获取最优图；
3. 时延用 `tools/bench_model.py` 的同一口径测，**不要用 FLOPs 代替时延**（见 B1 README 的反直觉结论）。

## 下一步

本阶段启动时，把窄化模型放进本文件夹的 `model.py`（暴露 `MODEL`），
加 `deploy/` 子目录放导出与基准脚本，结果并入部署对比表。
