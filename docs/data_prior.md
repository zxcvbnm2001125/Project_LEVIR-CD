## 2. 正样本占比（全分辨率统计）

| split | 变化像素占比 | 含变化的影像 |
|---|---|---|
| train | **4.59%** | 398 / 445 = 89.4% |
| val | **4.20%** | 56 / 64 = 87.5% |
| test | **5.09%** | 118 / 128 = 92.2% |

**推论（这些才是面试要讲的东西）**
1. 正负比 ≈ **1 : 19** → 单 BCE 会收敛到「全 0 也不亏」，必须 Dice 或组合损失。
2. 8–11% 影像**完全没有变化** → 全 0 预测的 OA 已达 ≈95%，**OA 不能当主指标**，必须看 F1 / IoU / 图斑级指标。
3. test 正样本率（5.09%）> train（4.59%）→ 测试略偏「变化多」，若训练集上过拟合到「少变化」先验，test 上 Recall 会偏高、Precision 偏低；报告里要提这一点。

## 3. 裁片协议（固定，不许中途改）

| split | 方式 | 块数 |
|---|---|---|
| train | 1024 不重叠切 16 块落盘；训练时再做翻转/旋转/多尺度 zoom | 445 × 16 = **7 120** |
| val | 不重叠 16 块（4×4） | 64 × 16 = 1 024 |
| test | 不重叠 16 块（4×4） | 128 × 16 = **2 048**（主表口径，与 SNUNet/BIT/ChangeFormer 一致） |

### 3.2 空块（无变化的裁片）该怎么处理？——**不删，用采样 + 加权**（2026-10-27 决策）

用户问过两次（第二次问得更准：既然全是背景，喂进去不是白烧算力吗），结论与依据记录在此，避免反复争论。

**先分清两类「空」**（train 7 120 块实测）：

| 类别 | 块数 | 占比 | 贡献的变化像素 |
|---|---|---|---|
| 完全无变化（change_px = 0） | 3 953 | 55.5% | 0（必然） |
| 近乎空（1–655 px，≤1% 面积） | 459 | 6.4% | 0.64% |
| 有实质变化（>1% 面积） | 2 708 | 38.0% | 99.36% |

**成本账（这才回答「会不会增加训练成本」）**
- 全喂：每 epoch 7 120 条；保留 35%：4 600 条（**-35% 时间**）；全删：3 167 条（再 -31%）。
- 按 256² / bs16 / ResNet34-UNet 估算（**未实测，等首次训练校准**）：4 600 条约 4 min/epoch，3 167 条约 2.7 min/epoch → 30 epoch 差约 **40 分钟**。
- 结论：**用 40 分钟换 Precision，这笔账划算**；但 55%→35% 这一刀已经砍过了，再砍收益递减、风险上升。

**为什么不能砍到 0**
1. **梯度是「按需」发生的**：模型在一个全背景块上预测正确时 loss≈0、梯度≈0 —— 它平时几乎不占「学习预算」，只占时间；一旦模型在这里误报（伪变化），梯度立刻很大。它是**哨兵**，不是陪练。
2. **它是「看见差别但答案是不变」的唯一监督**：本项目实测 A/B 两期影像本身就有大范围辐射差异（变化区内/区外灰度差之比仅 1.29×，见 §3.1）。全删后模型只会学到「两期不一样 = 变化」。
3. **val/test 绝对不能删**：test = 2 048 块（含 1 113 个纯空块）是指标口径，删了 F1 与文献不可比，而且**空块误报率**这个指标就没了（实验 #16）。

**比「删/不删」更好的第三方案：hard-negative 采样**（已实施，决策与数字见 `docs/hardneg_decision.md`）
- 真正值钱的负样本不是随机纯空块，而是「A/B 差异大、但 label 为空」的块（季节/阴影/配准误差造成的伪变化）。
- 做法：用亮度归一化后的 `P95(|A−B|)` 给全部 3 953 个空块打分（`data/score_empty.py`），取 top 30% 作负样本，单源最多 10 块；**分数最高的 1%（40 块）进人工复核队列、不入训练**（实测这批里约 5–15% 是漏标）。结果：cutoff=2.078，入选 1 186 块，覆盖 313 对源图，见实验 #15。
- 预期：同样训练时长下 Precision 更好，且「伪变化抑制」这条业务指标（§4.2）有据可讲。

**如果以后确实要省磁盘**（不是为了省算力）
- 空块 A/B 转 JPEG q90（约省 60%），label 保持 PNG（二值不能被压缩失真）；
- 或调小 `empty_keep_ratio` 后重建 crops（`manifest.csv` 同步重写，保持可复现）；
- 不要手工删文件。

> 面试价值：被问「正负样本不平衡怎么办」，好答案是「按层采样 + 难负样本挖掘 + 在 test 上单列空块误报率」，而不是「我把负样本删了」。空块比例 0 / 15 / 35 / 100 的四组对照已经排进 `EXPERIMENTS.md` #12–#14。

## 4. 连通域（图斑）面积分布（已实测，`data/priors.py`，8 邻域）

| split | 连通域数 | 每图图斑 | p50 | p90 | max |
|---|---|---|---|---|---|
| test | 7 027 | 54.9 | **805 px** | 1 426 px | 56 106 px |
| val | 2 788 | 43.6 | 888 px | 1 467 px | 60 885 px |
| train | 21 476 | 48.3 | 862 px | 1 424 px | 73 337 px |

面积分档（test）：

| 分档 | 占图斑数 | 占变化像素 |
|---|---|---|
| < 40 px（≈10 m²） | 0.8% | 0.0% |
| 40–80 px | 0.5% | 0.0% |
| 80–500 px | 11.9% | 4.0% |
| > 500 px | **86.7%** | **95.9%** |

**这张表推翻了一个直觉，必须写进报告和面试答案：**
1. LEVIR-CD 的标注**图斑本来就大**（中位数 805 px ≈ 200 m²），<80 px 的图斑只占 **1.3%**、像素占比 ~0%。
   → 所以 **MMU=80px 在 LEVIR 上几乎不剔除任何东西**，它不是性能杠杆，只是「交付链路能力」的演示。
   → **不要在简历/面试里吹「小目标检测能力」**，会被这张表当场打脸。小目标是在 80 cm 分辨率数据/车辆船只有效目标上的事，不是 LEVIR。
2. LEVIR 的真实难点 **不是小目标**，而是：① 边界精度（大斑块占 96% 像素，边界差 1px 就掉 IoU）；② 伪变化（阴影/季节/配准误差）；③ 新增 vs 拆除的混淆（外观对称）；④ 预测碎斑（模型输出比标注碎，图斑级 Precision 低）。
3. 因此后处理的目的是 **合并碎斑、平滑边界**，而不是「滤除小目标」；评价它要用**图斑级 Precision / 碎斑数**，不是像素 F1 的微小变化。

> 这组数字是面试第 17 问的分水岭：能说出「我原来以为 MMU 很重要，实测发现 LEVIR 的图斑中位数 805px，MMU 只影响 1.3% 的图斑，所以我把重点转到边界和伪变化」—— 这是真做过的人才会说的话。
