# 四类错误图册（阶段 A-5）

> 脚本 `tools/error_atlas.py`，产物 `run/error_atlas/mask_slide/`。
> 口径：test 128 张整幅拼图，M1·seed42，滑窗口径，thr 0.5，MMU=80 之前的原始预测。
> 四张图册：`atlas_FN.png` / `atlas_FP.png` / `atlas_boundary.png` / `atlas_pseudo.png`，
> 每类 3 例 × 5 列（A / B / GT / 预测叠加 / |A−B| 亮度差）。

## 1. 四类的判据（判据不同，结论才有区别）

| 类别 | 判据 | 回答的问题 |
|---|---|---|
| **漏检 FN** | 未匹配的真值斑块，且存在 ≥500 px 的整块漏检 | 哪些该报的没报 |
| **误检 FP** | **距最近真值 >5 px** 的预测像素（贴边的不算），且斑块 ≥500 px | 报了不该报的 |
| **边界** | TP 容量足够（>20 000 px）但 Boundary IoU 低 | 边界差在哪、是哪种差 |
| **伪变化** | 上述"独立误检"中，`\|ΔL\| < 12/255` 的部分 | 影像没变却被报警 |

两条阈值是刻意设的：

- **5 px 边缘容差**：贴着真值边界 1–5 px 的误报是**边界溢出**，属于边界精度问题；
  如果把它算进"误检"，FP 类就变成了 boundary 类的同义词，两类的结论都说不清。
- **500 px 最小斑块**：碎片已由 A-3 的 MMU 过滤处理，图册只讲"成块的错误"。

## 2. 最重要的发现：误报的结构

把全部 FP（549 406 px）按"离真值多远"拆开：

| 成分 | 像素 | 占 FP | 说明 |
|---|---|---|---|
| **贴着真值边界（≤5 px）** | 427 077 | **77.7%** | 边界溢出，不是"报错地方" |
| 独立误检（>5 px） | 122 329 | 22.3% | 真正"画在别处" |
| ├ 其中影像**确实变了**但 GT 没标 | 107 089 | 19.5% | 口径问题（非建筑变化） |
| └ 其中影像**几乎没变**（伪变化） | 15 234 | **2.8%** | 模型过敏 |

这个分解直接改写了对模型的评价：

> **模型的误报里，77.7% 是边界画大了一点，19.5% 是报了「影像确实变了但标注不标」的东西
> （拆除、工业罐体、施工场地），真正"无中生有"的只占 2.8%。**

配套的漏检侧：FN 700 933 px，占真值面积 **10.25%**。

## 3. 四类各自的结论

### 3.1 漏检（`atlas_FN.png`）

代表例：`test_82`（FN 34 287 px，漏检率 64%）、`test_77`（13 037 px / 21.5%）、`test_80`。

三例的共同形态：**A 期是空地或老旧厂房，B 期整片新建小区/厂区**。
GT 是一整块大面，预测只覆盖到边缘或其中几栋。

看第 5 列 `|A−B|` 就能明白原因：这类区域整片都在发亮，说明影像**变化幅度极大**，
模型的输出却只在高置信度的核心区收敛。典型成因是**训练集里这种"整片推平重建"的样本太少**
（LEVIR 多数样本是零星加建），模型没见过这么大的连续变化面。

> 可执行对策：按 GT 斑块面积做重采样（大斑块过采样），或对大斑块用更高的 loss 权重。
> 这比调阈值有效——降阈值会把边界溢出一起放大。

### 3.2 误检（`atlas_FP.png`）

代表例：`test_33`、`test_10`、`test_72`，三例**独立误检区域的 `|ΔA−B|` 都在 55–95**
（亮度差满量程 255 的三分之一以上），说明影像确实变了。

- `test_10`：A 期一个灰色储罐，B 期被刷成亮白色并有新罐——**工业设施翻新**，LEVIR 只标建筑；
- `test_33`：B 期新增红色屋顶棚架，GT 只标了旁边一小块；
- `test_72`：A 期厂房，B 期部分拆除——**拆除类变化**的标注不完整。

结论：**这一类的责任主要在标注口径，不在模型**。模型确实"看见"了变化，只是这个变化
不在数据集的定义里。报告里必须这样写，否则会被误读成"模型乱报"。

### 3.3 边界（`atlas_boundary.png`）

代表例：`test_45`（BndIoU 0.640）、`test_20`（0.650）、`test_115`（0.647），TP 都在 16–24 万像素。

**目视印象与量化结果不一致，这里必须记录**：从图上第一眼看去，绿色预测块比白色 GT 块"小一圈"，
很像是系统性内缩。但用 `run/patch_metrics/mask_slide/match_pairs.csv` 的 6 157 对匹配量化后：

| 面积比 pred/gt | p10 | p25 | **p50** | p75 | p90 | <1 占比 |
|---|---|---|---|---|---|---|
| 数值 | 0.882 | 0.949 | **1.004** | 1.056 | 1.126 | 48.0% |

中位数 1.004、48% 内缩 / 52% 外扩 → **没有系统性偏差，是双向抖动**（±1–2 px 的定位误差）。
目视"看起来内缩"是半透明绿色叠加在暗色屋顶上的视觉错觉。

这条结论的价值在于：如果按"内缩"去改（比如膨胀后处理），会把 52% 本来已经外扩的图斑推得更糟。

> 正确对策是提高边界定位能力：边界加权损失、更高分辨率（256→512）、或多尺度融合。
> **不是后处理**——后处理只能整体平移边界，无法修正随机抖动。

### 3.4 伪变化（`atlas_pseudo.png`）

代表例：`test_106`、`test_113`、`test_103`，低对比度误报面积 1 058 / 941 / 698 px。

这一类在本数据集上**不典型**，占比仅 2.8% of FP。原因很直接：
LEVIR 的两期影像相隔 5–14 年，变化是真实的，几乎不存在纯光照/季节造成的伪变化。

> 因此本项目**不需要做伪变化抑制模块**。这也解释了为什么 M1 的差分项虽然在冒烟阶段
> 把空块误报从 9.74‰ 压到 2.96‰，正式训练后 M0（0.59‰）与 M1（0.61‰）却完全打平——
> 该数据集本来就没有多少伪变化可供抑制。

如果将来要验证伪变化抑制，必须换数据（同季节/跨季节的高分影像对），否则测不出差异。

## 4. 对下一步的四条指导

| # | 结论 | 动作 | 优先级 |
|---|---|---|---|
| 1 | 误报 77.7% 是边界溢出 | 边界加权损失 / 512 裁片 | 高（唯一能实质提分的） |
| 2 | 漏检集中在"整片重建"大斑块 | 按 GT 斑块面积重采样、大斑块加权 | 中 |
| 3 | 误检 19.5% 是口径问题 | 报告里如实说明，不当作模型缺陷 | —（写清楚即可） |
| 4 | 伪变化仅 2.8% | 不做伪变化抑制模块 | 已排除 |

## 5. 复现

```bash
# 全量扫描 + 自动选样 + 出四张图册（约 5 分钟）
python tools/error_atlas.py --pred-dir run/slide/test_M1_seed42_thr0.5/mask --suffix _slide

# 只出统计、不出图
python tools/error_atlas.py ... --no-figure

# 调整判据
python tools/error_atlas.py ... --min-patch 1000 --per-cat 5
```

产物：`atlas_{FN,FP,boundary,pseudo}.png`、`cases.csv`（每例的指标与错误质心）、`summary.json`。

## 6. 已知局限

1. **选样靠打分规则，不是人工精选**。打分保证了"错误最严重的那几张"，但"最能说明问题的那几张"
   仍需人工再过一遍——目前 12 例是可用的，但不能保证是全局最优的代表。
2. **伪变化判据只有亮度差**（`|L_A − L_B|`），对"同亮度但结构变化"（如屋顶换材质）不敏感。
3. **`|A−B|` 热图上限固定 60**，超过即饱和，特大片变化区域看不出层次。
