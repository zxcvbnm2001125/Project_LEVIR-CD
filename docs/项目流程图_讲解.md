## 2. 图 1 怎么读（6 周路线图）

每一行就是一周，五列分别回答五个问题：

1. **阶段** —— 左边彩色块，颜色越往后越"危险"（灰=准备、蓝=搭基础、紫=做方法、青=稳数据、橙=交付+投递、绿=包装、红=面试）。
2. **这一周要干成什么** —— 一周只干这一件事，别贪多。
3. **门槛（拿不到怎么办）** —— ⭐ 最重要的一列。橙色框里是**必须达到的数字或状态**。没有门槛的周会无限拖延，所以每周都设了刹车。
4. **周结束时手里必须有** —— 产出物。**没有产出 = 这周没做**（哪怕是"我调了很多参数"，也算没做）。
5. **不达标的处理** —— 红字。这一列是写给"卡住时的你"看的，避免你在某一周反复打转把 6 周耗完。

> 为什么每周门槛这么低（0.82 → 0.86 → 0.88）？
> 因为这是**流水线检查点**，不是最终目标：0.82 只证明"数据能进、指标脚本没 bug"；0.86 证明"我的改动有效"；0.88 才是写进简历的数字。**卡在 0.82 说明管线有问题，不是模型不行** —— 这个判断能救你 2 周。

## 3. 图 2 怎么读（详细步骤）

四种图形，含义固定：

| 图形 | 含义 | 你要做的动作 |
|---|---|---|
| 白色方块 + 编号（如 `1.2`） | 一个具体任务 | 动手做；编号就是你在计划里的引用号（"我在 1.2"） |
| 方块右下角灰色小字（如 `1 天`） | 预计耗时 | 超时 2 倍就停下想想是不是卡住了 |
| 橙色**菱形** | 判定点（周门槛） | 拿数字比对：达到走"是 ↓"，没达到看红字 |
| 右侧**绿色框** | 产出物 | 必须是**能打开给别人看的东西**（文件、图、表、数字） |

底部还有一条「内循环」——全项目会重复约 20 次，**每一步实验都走这 6 个动作**：

```
写假设 → 只改一个变量 → 训练 2–3 小时 → 统一脚本评估 → 记一行 EXPERIMENTS → 看结论定下一步
```

对小白来说，这条循环比任何模型结构都重要：**它是"结果可信"的唯一保证**，也是面试官判断"这人是不是真做过"的地方。

## 5. 新手最容易踩的 5 个坑（图上的红字都是在防这些）

1. **急着换模型。** 数字低时 90% 是数据/评估的问题，不是模型。→ 所以 W2 明确规定"不换模型，只调参"。
2. **A/B 不同步增强。** 会给模型喂"人为制造的假变化"，指标虚高、上线崩。→ Dataset 里必须同步。
3. **只看 F1，不看图和图斑。** 像素 F1 0.88 但输出满屏碎斑，业务上不能用。→ W4 必须算图斑级指标。
4. **没有基线就报提升。** 没有 B0 对照，"我的方法好"这句话不成立。→ W1 必须先把 B0 跑出来（这就是为什么 B0 在 W1 不在 W2）。
5. **指标脚本没验证就信它。** 一个 bug 能让 F1 差 0.1。→ 1.3 用"全 0 / 全 1 预测"两个极端值自检（应得 F1≈0 和 F1≈0.1）。

## 6. 术语表（图里出现的词，一句话版）

| 词 | 一句话解释 |
|---|---|
| **变化检测** | 给同一地方的两期影像（A=前、B=后），标出"哪里变了" |
| **A / B / label** | A=前期影像，B=后期影像，label=人工标注的"变化区域"（0/255 单通道） |
| **裁片（crop）** | 把 1024×1024 大图切成 256×256 小块再喂给模型（显存装不下大图） |
| **F1** | 精确率和召回率的折中，0–1，越高越好；本项目主指标 |
| **IoU** | 预测区域与真实区域的交并比；F1 与它基本同向，但 IoU 对"大目标"更敏感 |
| **OA** | 总体准确率。**本项目不能看它**：全预测 0 就有 95%（因为变化像素只占 5%） |
| **Precision / Recall** | 查得准 / 查得全。漏检多了 Recall 低，误检多了 Precision 低 |
| **Kappa** | 扣掉"瞎猜也能猜对"那部分后的一致性，比 OA 诚实 |
| **BCE / Dice** | 两种损失函数。样本极不平衡（1:19）时 BCE 容易"全预测 0"，Dice 直接优化重叠度 |
| **seed（随机种子）** | 固定它才能复现；换 3 个 seed 跑，报 mean±std 才可信 |
| **消融实验** | 一次只去掉/加上一个模块，看指标变化，证明"是这个改动起了作用" |
| **图斑（连通域）** | 把像素结果连成一块块的"斑"，业务上交付的是图斑不是像素 |
| **MMU（最小上图面积）** | 小于这个面积的图斑不入库。本项目实测：LEVIR 图斑中位数 805px，MMU=80 只影响 1.3% |
| **Boundary IoU** | 只看边界附近算的 IoU，衡量"边缘画得准不准" |
| **滑窗推理** | 大图切块分别预测再拼回去（要重叠，否则接缝处会断） |
| **ONNX / TensorRT** | 模型导出格式 / 英伟达推理加速引擎；配 fp16、int8 量化 |
| **伪变化** | 地物没变，但因光照、阴影、季节、配准误差被误判为变化 |
| **正/负样本** | 正 = 这块**有**变化（label 有像素）；负 = 这块**没**变化（label 全 0） |
| **难负样本 hard negative** | 负样本里"长得像正样本"的那批：两期看着不一样，正确答案却是"没变"。详见 §6.1 |
| **闸门（gate）** | 固定日期的硬性检查点，没过就不往下走（防止"什么都做了但什么都没做完"） |

### 6.1 什么是 hard negative（难负样本）

**一句话**：负样本里，**模型最容易判错的那一小撮**。

把负样本按"模型有多容易把它误判成变化"排个队：

| 类型 | 长什么样 | 模型的 loss | 对训练的价值 |
|---|---|---|---|
| **简单负样本** | A/B 两期几乎一模一样（同一季节、同一光照、纯草地） | ≈ 0，梯度 ≈ 0 | 几乎没有。占时间，不占"学习" |
| **难负样本** | A/B **明显不一样**（冬夏、树影、新修的小路、配准偏 1–2 像素），但 label 是空的 | 大，梯度大 | **最高**。它逼模型学会"看着不一样 ≠ 变化" |
| （正样本被漏掉的） | label 写"没变"但其实变了 → 标错了 | 大，但是**错的**梯度 | 负价值，必须靠人眼排查 |

**为什么叫"难"**：难点不在数据难，而在它对模型难——它正好压在决策边界上。简单负样本模型早就"闭眼答对"，再喂一万个也没用；难负样本每喂一次都在纠正模型的一个具体误解。

**类比**：刷题只做会做的题，分数不动；**错题本**才涨分。难负样本就是负样本里的"错题本"。

**怎么在本项目里找出来**（`data/score_empty.py`，纯 CPU）：
1. 只看 train 里 label 全 0 的 3 953 个块（负样本池）；
2. 给每块算一个"两期差异分"：先把 A、B 各自减均值除标准差（**消掉整体亮度差**），再算 `|A−B|`，取 95 分位像素差 —— 这样"整体变亮"不算差异，"结构变了"才算；
3. 按分数排序，取 **top 30%** 当难负样本；
4. **抽样人眼复核**：把 top 200 拼成一张大图看——如果它们真的是"两期不同但没建筑变化"，说明打分有效；如果发现"明明有新建建筑却被标成没变"，那就是**标注错误**，顺手质检（难负样本挖掘天然兼任标注质检）。

**两个必须防的坑**
- **别只按全局亮度打分**：季节差最大的块分数最高，但它们往往是最"简单"的负样本（树全黄了，但建筑没动）。所以要先做亮度/对比度归一化，再看结构差异。
- **别让 top 30% 全来自同几对源图**：按源图分组限流（每对源图最多取 10 块），否则难负样本退化成"那几对季节错配的图"，多样性归零。

**面试时怎么讲**（这是加分句，不是背术语）：
> "负样本我没删，而是做了难负样本挖掘：用亮度归一化后的结构差异分排序，取 top 30% 作为训练负样本，并抽查 200 张发现 3 张标注漏标——所以这一步同时也是标注质检。对照实验里，难负采样比随机采样在同训练时长下 Precision 高 X 个点。"
